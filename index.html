VoidUI A universal, decoupled developer desktop interface tool

Point it at an API. It becomes an app.

VoidUI is a small native window that renders whatever your HTTP API returns. Send it your markup and it shows it. Send it JSON in the 3PaneApp layout and it builds a browsing workspace. Or point it at a PDF, a spreadsheet, a CSV. Write the backend in Python, Rust, C++, or host the JSON somewhere else entirely. The viewer never asks what language you used.

One endpoint, two shapes

VoidUI calls a single URL on your server. The response is always JSON; the type field decides what you get: your markup, or JSON laid out for the 3PaneApp view — categories on the left, items in the middle, the document on the right. There is no plugin system and no language binding — your daemon is just an HTTP server that returns the right bytes.

Option 1 — send HTML
// GET http://127.0.0.1:8787/api/data
// Header: X-API-Key: your-key
{
  "type": "html",
  "title": "My Dashboard",
  "content": "<h1>Processed 42 records.</h1>"
}

Your markup goes straight into the reading pane. One field, and you have a desktop app.

content can be a fragment or a whole document — a <table>, a chart, a canvas sketch. Inline event handlers such as onclick work; a <script> tag does not run, because the markup is inserted rather than parsed as a page.

Option 2 — send a 3PaneApp catalog
{
  "type": "json",
  "layout": "3pane",
  "categories": [
    {
      "id": "docs",
      "title": "Documents",
      "items": [
        {
          "id": "rfc",
          "title": "RFC 9110",
          "format": "pdf",
          "url": "https://.../rfc9110.pdf"
        }
      ]
    }
  ]
}

Categories on the left, items in the middle, the file on the right. The `layout` has to be 3pane and the fields have to match what the player expects — the exact list is in Creating daemons.

What you can write it in

The bundled examples are Python, and each one ships as a Windows binary — no interpreter, no install step. The protocol itself is HTTP and JSON, so any language can serve it.

Python — Flask, FastAPI, anything Rust — axum, actix C++ — any HTTP server Go — net/http Node, C#, Elixir A static JSON file on any host

A daemon publishes a format and a url — never the file bytes. The player downloads and parses the file itself, so a 40 MB spreadsheet costs your server nothing.

Three steps

No build step for the viewer, no build step for the daemon, no framework to adopt.

Write an endpointany http server
Answer /api/data with JSON and check the X-API-Key header. Inside that JSON, set type to html or json and fill in the matching shape. That is the whole requirement.
Run itlocalhost, or a hosted URL
A local daemon on 127.0.0.1 is the usual case. It also works against a hosted endpoint: put the host in Daemon Host / URL, the port in Port, and hand out API keys yourself. The player talks to it over plain HTTPS.
Point VoidUI at itsettings → save & connect
The window polls, renders, and keeps your data live. Test Connection tells you whether the endpoint answers before you commit to it.

What it can render

The player downloads each file and parses it in the browser — ZIP and OOXML included, with no third-party library and no Office install on the machine.

FormatRenders asAlso
htmlYour markup, injected into the reading paneThe simplest mode — one field, done
jsonSyntax-coloured tree3PaneApp mode, or a raw dump
pdfEmbedded reader with page countOpens in the webview's own viewer
docxHeadings, lists and tables as a documentWordprocessingML, parsed directly
xlsxCell grid with sheet tabsShared strings and inline strings
csvTable with live row filteringHandled as a table, not a file
audioEmbedded playerWith track metadata
video / m3u8Adaptive stream playerNeeds CORS headers on the host

Every format except streaming is downloaded by the player's own backend, so it works no matter what headers your server sends. Playlists are the exception: the browser fetches them directly, so the host has to allow cross-origin requests.

Why not Electron
